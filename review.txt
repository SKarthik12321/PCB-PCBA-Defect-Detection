## 🎓 Viva Preparation: Algorithms & Techniques

### 1. What is the Core Algorithm?
- **YOLO11 (You Only Look Once)**: A state-of-the-art real-time object detection model.
- **Why YOLO11?** It provides the best balance between **Inference Speed** (critical for our live webcam feature) and **Mean Average Precision (mAP)**.
- **Improvements**: YOLO11 uses a more efficient backbone (C3k2 modules) and a segmented detection head for better tiny-object localization.

### 2. Specialized Techniques (Conceptual Architecture)
- **DACSR (Domain Adaptive Cross-Scale Representation)**: Solves the "tiny defect" problem. It merges high-resolution spatial maps with deep semantic features so that a 1-pixel "mouse bite" is detected as easily as a large "missing hole."
- **CARFT (Context-Aware Receptive Field Tuning)**: Prevents false positives. On a PCBA with thousands of components, CARFT helps the model distinguish between a valid small component and a actual defect by looking at the surrounding context (e.g., if it's on a pad or a trace).

### 3. Data Preprocessing & Augmentation (In-Depth)
- **Template Neutralization & Pre-alignment**:
    - **Concept**: Since PCB inspection is highly sensitive to lighting and board positioning, we use the "Template" image as a reference.
    - **Technique**: We perform alignment (Image Registration) so the test image perfectly overlays the template. Any deviation in the pixel intensity helps the model differentiate between the background circuit and a defect.
- **YOLO-specific "Mosaic" Augmentation**:
    - **Mechanism**: We stitch together 4 different training images into a single frame.
    - **Impact**: This forces the model to detect objects at much smaller scales and handles the "Center Bias" problem (where models only expect objects in the middle of the screen). This is crucial for detecting tiny mouse bites which can occur anywhere on the board.
- **Advanced Augmentation (Albumentations)**:
    - **Geometric Transforms**: Random Rotation (0-360°), Vertical/Horizontal Flips, and Perspective shifts. These are vital because a PCB can be placed on the inspection bed in any orientation.
    - **Photometric Transforms**: Adjusting brightness, contrast, and adding Gaussian noise. This simulates different camera qualities and lighting conditions in a factory.

### 4. How do we evaluate accuracy? (The Math)
- **Intersection over Union (IoU)**:
    - This is the ratio of the "Overlap Area" to the "Total Combined Area" of the predicted box and the real defect box. An IoU of 1.0 is a perfect match.
- **Precision vs. Recall (The Industrial Trade-off)**:
    - **Precision (Exactness)**: "Of all the defects we flagged, how many were REAL?" (Prevents stopping the production line for fake defects).
    - **Recall (Discovery)**: "Of all the real defects on the board, how many did we FIND?" (Crucial in safety-critical PCBs—we cannot afford to miss a single 'Short').
- **mAP@0.5 (Mean Average Precision)**:
    - We calculate the "Average Precision" for each of the 6 classes (missing hole, mouse bite, etc.) and take the mean. The "@0.5" means we count a detection as a "Success" if the IoU is at least 50%.
- **mAP@0.5:0.95 (Strict Precision)**:
    - This is the gold standard. It averages precision across multiple IoU thresholds (50% to 95%). It rewards the model for drawing extremely tight and accurate bounding boxes, not just "vague" ones.
- **F1-Score**:
    - The harmonic mean of Precision and Recall. It provides a single number that tells us if the model is well-balanced or leaning too heavily toward one side.

### 5. Optimization for Deployment
- **AMP (Automatic Mixed Precision)**: We train using 16-bit floats instead of 32-bit. This speeds up training by 2x-3x without losing precision.
- **ONNX Export**: We convert the PyTorch (.pt) model to ONNX format to allow hardware acceleration on different CPU/GPU architectures.
- **CORS Middleware**: Implemented in FastAPI to ensure the React frontend (running on a different port) can securely talk to the model server on localhost.
